# Paul Chege Consultancy TV — static site

Plain HTML, CSS and JavaScript. No npm install, no build step, no CDN for the
app itself. **Every page is a real file with its own URL, title and link
preview.**

```
index.html    /                 home
about/ services/ book/ tv-hub/ calculator/ booking/ faq/ contact/
privacy/  terms/                legal
404.html                        served for unknown paths
config.js  ←  live settings: paste your keys here, no rebuild
assets/app.css  79 KB  ·  assets/app.js  359 KB (102 KB gzipped)
img/          WebP artwork + the 1200×630 share card
downloads/    the free Offer Letter Checklist PDF
pages/*.html  script-free copies, for templating
robots.txt · sitemap.xml · _redirects · vercel.json
```

## Run it

```bash
python3 -m http.server 8080
```

Deep links work without server rewrites — each route is a real folder with its
own `index.html`. `_redirects`, `vercel.json` and `404.html` cover Netlify,
Vercel and GitHub Pages.

## Going live — edit one file

Open **`config.js`**, paste your values, save, reload:

```js
window.PC_CONFIG = {
  contact:  { provider: "web3forms", key: "YOUR-WEB3FORMS-KEY" },
  booking:  { provider: "sheets",    url: "https://script.google.com/.../exec" },
  calendly: { free: "https://calendly.com/<you>/30min",
              paid: "https://calendly.com/<you>/60min" },
  site:     { origin: "https://paulchege.co.ke", basePath: "/" },
};
```

Blank values keep that feature in demo mode, and the page says so on screen.
**`site.origin` drives every canonical URL and link preview** — change it
before launch, along with `robots.txt` and `sitemap.xml`.

## Lead magnet

`downloads/offer-letter-checklist.pdf` — a 3-page branded PDF, 29 checklist
items, generated by `source/tools/build-leadmagnet.py`. Edit the `SECTIONS`
list in that script and re-run it.

The capture band sits on the calculator, book and FAQ pages. It posts the name
and email through the **same Web3Forms endpoint as the contact form**, tagged
"Free download", then reveals the file. If the POST fails the download still
works — the file is never held hostage to a failed request.

## SEO

Per-page `<title>`, meta description, canonical, Open Graph and Twitter cards
pointing at `img/share-card.webp` (1200×630). `sitemap.xml` lists eleven pages;
`robots.txt` allows everything and sets `max-image-preview:large`.

Structured data, baked into the served HTML of every page:

| Schema | Where | What it can earn |
| --- | --- | --- |
| `Person`, `ProfessionalService`, `Book` | every page | knowledge panel, `sameAs` to all four profiles |
| `BreadcrumbList` | every page | breadcrumb trail in results |
| `WebSite` + `SearchAction` | home | sitelinks search box |
| `FAQPage` | `/faq` | expandable Q&A directly in results |
| `VideoObject` ×9 | `/tv-hub` | video thumbnails in results and the Video tab |
| `Service` ×3 | `/services` | service rich results |
| `Service` + offers | `/booking` | price shown for the paid session |

Also `lang="en-KE"` on the document and `lang="ki"` on Kikuyu titles,
`theme-color` per colour scheme, geo meta for Nairobi, preconnect to
`i.ytimg.com`, exactly one `<h1>` per page (verified), and an accessible name
on every control (verified).

Validate with Google's Rich Results Test once the real domain is live.

## Regenerating the static pages

`npm run build` produces the SPA. The prerendered route folders and
`pages/*.html` are then captured from the running site in a browser, after
which `python3 tools/finish-static.py` writes the 404, fixes templating paths,
prunes superseded images and regenerates robots/sitemap/host configs.

## Payments

M-Pesa is **real** and lives in `server/` — see `server/README.md`. A buyer
gets a Safaricom prompt on their handset, the money goes into Paul's own
shortcode, and the eBook downloads to their device the moment Safaricom
confirms. `npm run test:mpesa` proves the whole chain (46 assertions) against
a local Safaricom emulator, without charging anyone.

**Running it is one command.** `npm run server` serves this site *and* the
payment API on the same origin, so there is no URL to configure — the page
asks `/api/health` and switches itself on. Real money needs the Daraja
credentials in `server/.env`; without them the checkout says plainly that
nothing will be charged.

Buying is a **page**, not a modal: `/checkout` has three steps on one URL,
and every order gets a permanent `/order/PC…` page that the receipt email
links to.

**Paid sessions** work the same way, with one extra rule: the seat comes off
the diary *before* any money is asked for, and is confirmed in the same breath
as the payment — so nobody is ever paid-up and seatless. The diary is real, so
it can say no, and two people cannot buy the same 10:00. Before the prompt
goes out the client is told the amount, the paybill and the registered name
that will appear on their own handset, given the licence number and the
address, and promised a refund with no process if Paul does not show. See
`server/README.md` → "Designed against the fear of being scammed".

**Google Meet** is wired in and optional. Connected, each confirmed session
gets a real Meet room, appears in Paul's calendar, and Google emails the
client the invite. Not connected — or if Google fails at the moment of
payment — the booking still confirms and the page says Paul will phone them.
It never shows a link it does not have. `npm run google:auth` does the
one-time setup.

**Email** — receipts, booking confirmations and reminders 24 hours and 1 hour
before a session. Optional; without it the site works exactly as before. Note
that Web3Forms *cannot* do this: it delivers to the account owner's inbox, so
a receipt to a buyer would only ever have reached Paul. Use Resend, Brevo,
Postmark or MailerSend — `server/.env.example` has the details.

`npm test` runs all four suites: 46 purchase, 45 booking, 30 Meet, 40 email.

## Still outstanding

Run `python3 tools/preflight.py` for the live checklist; it exits non-zero
while anything below is unresolved.

- **Unsourced statistics: none.** Every number on the site now names where it
  came from. The brand sheet's "10K+ happy clients", "4.8/5 rating" and
  "KES 312,000 average saving" have all been removed — they could not be
  verified, and a regulated intermediary cannot advertise them.
- **Testimonials.** `TESTIMONIALS` in the source is an empty array by design.
  Add entries only once a real client has agreed **in writing** to be quoted,
  recording the consent date in the `consent` field. The proof section renders
  an invitation instead while the array is empty; the contact form has a
  "Share my experience" topic that captures that consent.
- **Legal.** Both `/privacy` and `/terms` are drafts written by a non-lawyer
  and say so in a banner. Before launch: have a Kenyan advocate review them,
  fill the three bracketed values in `const ENTITY` (registered entity name,
  ODPC registration number, IRA licence number — the licence also shows in the
  footer), confirm the 7-year retention periods against Paul's actual
  obligations, then delete the banner in `LegalDoc`.
